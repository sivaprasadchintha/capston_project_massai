Module 2 – Analytics

Overview

This module performs exploratory data analysis (EDA) and machine-learning modeling on the Titanic dataset.

The analytics workflow is implemented primarily in two Jupyter notebooks:

01_eda.ipynb — dataset profiling, missing-value handling, exploratory analysis, visualizations, survival-rate analysis, and standardization checks.

02_modeling.ipynb — classification, class-imbalance handling, hyperparameter tuning, model evaluation, linear regression, and model persistence.

The module also contains eda_visualizations.py, which keeps the EDA chart-generation functions reusable and organized.

Missing-Value Handling

The notebook applies the following rule-based strategy:

Missing percentage

Strategy

< 5%

Drop affected rows

5%–30%

Impute missing values

> 30%

Drop the column

For numeric columns in the 5%–30% range, median imputation is used.

For categorical columns in the 5%–30% range, mode imputation is used.

Module 2.2 – Machine Learning Modeling

Target and Feature Selection

The classification target is:

survived

The following columns are removed from the feature matrix:

survived
alive

alive is removed because it directly represents the target outcome and would create target leakage.

Train-Test Split

The dataset is split using:

train_test_split(
    X,
    y,
    test_size=0.20,
    random_state=42,
    stratify=y
)

Therefore:

80% is used for training.

20% is used for testing.

random_state=42 makes the split reproducible.

Stratification preserves the target-class distribution.

Preprocessing

Numeric features are standardized using:

StandardScaler

Categorical features are encoded using:

OneHotEncoder(handle_unknown="ignore")

A ColumnTransformer combines the numeric and categorical preprocessing pipelines.

Class-Imbalance Handling

The notebook compares three approaches using Random Forest:

1. Baseline

Standard Random Forest without class balancing.

2. Balanced Class Weights

Uses:

class_weight="balanced"

3. SMOTE

Synthetic Minority Over-sampling Technique is applied to the processed training data.

The three methods are compared using:

Precision

Recall

F1 Score

The method with the highest F1 score is identified as the preferred imbalance-handling approach.

Hyperparameter Tuning

Random Forest hyperparameters are tuned using GridSearchCV.

The search space includes:

n_estimators:
    100
    200

max_depth:
    5
    10
    None

min_samples_split:
    2
    5

Five-fold cross-validation is used with:

scoring="f1"

The resulting best estimator is used for model persistence.

Out-of-Bag Evaluation

An additional Random Forest model is trained with:

oob_score=True

The Out-of-Bag score is reported as an additional validation measure.

Linear Regression Analysis

The project also performs a regression task to predict:

fare

The regression workflow:

Uses fare as the target.

Removes fare from the feature matrix.

One-hot encodes categorical features.

Splits the data into training and test sets.

Standardizes the features.

Trains LinearRegression.

Generates predictions.

Calculates regression metrics.

Metrics:

MAE

RMSE

R²

Adjusted R²

A residual plot is generated:

Reproducibility

The project uses fixed random seeds in the major machine-learning workflows, including:

random_state=42

This helps make train/test splitting and model training reproducible.

Because the EDA notebook initially loads the dataset from Seaborn, an internet connection may be required when recreating titanic.csv from scratch. Once titanic.csv exists, the modeling notebook can use the local file.
